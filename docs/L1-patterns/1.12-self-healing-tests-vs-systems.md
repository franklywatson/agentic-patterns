# Pattern 1.12 — Self-Healing Tests vs Self-Healing Systems

This pattern is a definition, so its evidence is Thin. It follows from this library's own rule that a test must be able to fail ([Pattern 1.6](1.6-test-integrity.md)). No source here covers self-healing tests.

## Problem

"Self-healing" names two opposite things. A self-healing test adapts its selectors, retries, or rewrites its expectations when it fails. It removes signal. A self-healing system restores correct behavior. It adds signal. Teams that buy a self-healing test product can believe they have self-repair. They do not.

## Solution

State the difference and hold to it.

**Tests never heal themselves.** A test that changes its own assertions on failure is a soft assertion with extra steps. A locator update is acceptable only as a proposed diff that passes through [Pattern 1.9](1.9-repair-loop-frozen-oracle.md) like any change, with the assertions protected.

**A test the repair loop wants to change means the spec changed.** That is a design decision, made through design and planning, not a repair.

**Systems heal at three depths**, in rising order of autonomy:

| Depth | What it does | Owner | Produces a learning |
|-------|--------------|-------|---------------------|
| Runtime recovery | Restart, failover, circuit breaker | Operations | No |
| Mitigation | Flag-off, rollback | Gate and rollback ([Pattern 1.10](1.10-production-gate-progressive-confirmation.md)) | No |
| Repair | A code change with a reproduction | The repair loop ([Patterns 1.7 to 1.11](../L1-feedback-loops.md#closing-the-loop-in-production)) | Yes |

**Recovery without a repair ticket is a masked defect.** If a restart clears the same failure twice, the cause is still in the code. The recovery must open a ticket with an owner, or the defect stays hidden.

## In Practice

- Count runtime recoveries per fingerprint. A fingerprint that recovers repeatedly with no open repair is a masked defect. Report it as the masked-defect rate ([Pattern 4.4](../L4-standards-measurement.md#pattern-44--agentic-development-metrics)).
- Open a root-cause ticket for every change the anti-masking scan reclassifies as a mitigation, even when it turns the reproduction green.
- Pod restarts can hide a memory leak indefinitely. A restart counter on the health endpoint ([Pattern 1.1](1.1-stack-tests.md#health-endpoint-test-mode)) makes the pattern visible.

## Anti-Pattern

- **Adopting a self-healing test product and calling it self-repair.**
- **A test that rewrites its own expected value** after a failure.
- **Runtime recovery with no ticket.**
- **Counting a mitigation as a fix.**
