# Pattern 1.9 — Repair Loop with a Frozen Oracle

The agent that writes the fix must not write, edit or grade the test that judges it. The reproduction is frozen before the fix, the fix may not touch existing tests, and a scan checks production diffs for code that hides the error instead of removing it.

## Problem

An agent that writes both the reproduction and the fix grades its own work. The cheapest way to turn a red test green is to change the test, widen a tolerance, or catch the exception. In production code, a swallowed exception is a soft assertion ([Pattern 1.6](1.6-test-integrity.md)): the error vanishes and the defect stays.

## Solution

A repair is accepted only when every condition below is true, checked by code:

1. **The reproduction is byte-identical to the frozen version.** It is hashed when it is written ([Pattern 1.7](1.7-incident-to-stack-test.md)). The repair agent has no write access to it. A permission holds this rule. An instruction does not.
2. **The reproduction was red on the base commit and is green on the candidate.**
3. **The full unit and stack suites are green** in an isolated stack ([Pattern 1.4](1.4-container-isolation.md)).
4. **The diff touches no existing test file.** The only test change allowed is the added reproduction.
5. **The anti-masking scan is clean** (below).
6. **The change is classified** ([Pattern 1.8](1.8-reversibility-blast-radius.md)). Anything above the grant's ceiling stops at a human.
7. **An evidence bundle exists** ([Pattern 4.1](../L4-standards-measurement.md#pattern-41--evidence-based-claims)): before and after output, the diff, the class and the scan result.

### The anti-masking scan

The scan applies the Pattern 1.6 rules to production diffs. A complete scan flags:

- a new `catch` or `except` that does not rethrow
- a new retry or backoff
- a longer timeout, ttl or deadline
- a lowered threshold, minimum or required count
- a new flag that defaults off on the failing path
- an early return on the error path
- a default value that replaces a missing one (`?? 0`, `Optional` with a fallback)

The example scan implements the first four. The last three are recommended rules it does not implement, and the
partial patch below (a guard that returns early) passes it.

A hit does not reject the change. It reclassifies it from a **fix** to a **mitigation**. A mitigation may ship, but a human decides, and a root-cause ticket with an owner opens automatically. See [Pattern 1.12](1.12-self-healing-tests-vs-systems.md).

## In Practice

[`examples/repair-loop/`](../../examples/repair-loop/README.md) runs four fixed patches against one incident (stack tests [03](../../examples/repair-loop/typescript/tests/stack/03-repair-masking-rejected.stack.test.ts), [04](../../examples/repair-loop/typescript/tests/stack/04-repair-test-edit-blocked.stack.test.ts) and [06](../../examples/repair-loop/typescript/tests/stack/06-confirmation-rollback.stack.test.ts) cover the mask, the test edit and the partial patch):

- `INC-001.fix.patch` removes the cause. The reproduction goes green, the scan is clean and the gate returns `auto`.
- `INC-001.mask.patch` wraps the failing call in a `try` block. The reproduction goes green, the scan hits, the gate returns `human` and a ticket appears in the outbox.
- `INC-001.test-edit.patch` edits the reproduction. Its hash no longer matches the frozen hash, so the gate returns `block`.
- `INC-001.partial.patch` guards only the literal id that was reported, with an early return. The oracle goes green, the scan finds nothing and the gate returns `auto`. The confirmation window then finds the same fingerprint on a neighbouring input and rolls the change back (stack test 06).

The scan is a heuristic. It misses masking that it does not recognize. Treat it as a floor, keep the human route for mitigations, and add a rule each time a review finds a new masking shape.

## Anti-Pattern

- **One agent writes test and fix.** The test then proves nothing.
- **A frozen test protected by instruction only.** Use a path permission or a hash check.
- **Treating a green reproduction as a fix.** A mitigation also turns it green.
- **Trusting the suite beyond its coverage.** A fix can pass the reproduction and break a journey no test covers.
