# Pattern 1.10 — Production Gate and Progressive Confirmation

Evidence for this pattern is Thin: one vendor playbook for the gate and one position paper for progressive access. Treat it as a design to adopt carefully and measure, not a proven practice.

A verified fix is still a deploy. Green stack tests are local evidence. Production behavior is the claim. A gate decides whether a change may proceed, and a staged rollout confirms the fix in production.

## Problem

Verification on a developer machine does not show how a change behaves under production traffic. If the repair agent can also decide that production confirmed its fix, it grades its own work a second time.

## Solution

**The agent may act up to the production gate and cannot pass it** ([AN-27](../references/sources.md)).

**The gate is deterministic code outside the agent.** It is a pipeline step or deploy hook. It takes the evidence bundle ([Pattern 1.9](1.9-repair-loop-frozen-oracle.md)) and the classes ([Pattern 1.8](1.8-reversibility-blast-radius.md)) and returns one of three results, resolved with the severity rule from [Pattern 2.3](../L2-behavioral-guardrails.md#composing-checks):

- `auto`: proceed to a staged rollout
- `human`: stop and send the bundle to a named person
- `block`: reject, with the reason

Only `auto` changes proceed, and only through progressive delivery:

1. **Roll out behind a flag or a canary** to a small share of traffic.
2. **Confirm under a rule declared in advance.** For example: zero occurrences of the incident fingerprint across at least N requests on the cohort, and an error rate no worse than the control. Code evaluates the rule. The agent does not.
3. **Require a minimum sample.** No errors on a path with no traffic is not evidence.
4. **Roll back automatically** when the rule fails or the window ends without enough traffic. Rehearse the rollback on a schedule ([AN-27](../references/sources.md)).
5. **Prefer flag-off to revert** when many changes land in quick succession, because a revert can undo unrelated work ([PO-28](../references/sources.md)).

Production confirmation is statistical, so it uses graded evidence. That is allowed only under the pre-declared rule and only for gates on reversible actions ([Pattern 4.1](../L4-standards-measurement.md#pattern-41--evidence-based-claims)).

## In Practice

The production mode of the health endpoint ([Pattern 1.1](1.1-stack-tests.md#health-endpoint-test-mode)) gives the confirmation step the same signals the stack tests used: status, per-dependency state and version.

The gate is a pure function of a typed evidence bundle, so it can be evaluated like any other decision layer ([Pattern 4.6](../L4-standards-measurement.md#pattern-46--context-eval)). Score it exactly, not with partial credit, and report pass^k (the share of runs in which all k repeats pass) over repeated runs.

```typescript
type Decision = { result: 'auto' | 'human' | 'block'; reason: string };

function gate(bundle: EvidenceBundle, policy: Policy): Decision {
  if (!bundle.reproductionHashMatches) return { result: 'block', reason: 'oracle edited' };
  if (bundle.antiMask.hits.length > 0) return { result: 'human', reason: 'mitigation' };
  if (rank(bundle.reversibility) > policy.maxReversibility) return { result: 'human', reason: 'reversibility' };
  if (rank(bundle.blastRadius) > policy.maxBlastRadius) return { result: 'human', reason: 'blast radius' };
  return { result: 'auto', reason: 'clean' };
}
```

[`examples/repair-loop/`](../../examples/repair-loop/README.md) simulates the confirmation step: after an `auto` result it replays the incident 50 times against the candidate stack and counts the fingerprint in the app logs, under a pre-declared rule. It simulates production confirmation. It does not prove it.

Each repair that uses a flag leaves a flag behind. Give flags a removal rule ([Pattern 0.8](../L0-foundation.md#pattern-08--aggressive-cleanup)).

## Anti-Pattern

- **The agent summarizes the canary.** The agent has then become the gate.
- **A confirmation window with no minimum sample.**
- **A gate that advises.** A gate that warns and lets the change pass is not a gate ([Pattern 2.3](../L2-behavioral-guardrails.md#pattern-23--hook-automation)).
- **Graded evidence on an irreversible action.** Statistical confirmation cannot undo a sent payment.
