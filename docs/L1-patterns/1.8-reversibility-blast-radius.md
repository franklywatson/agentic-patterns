# Pattern 1.8 — Reversibility and Blast-Radius Classes

Classify every proposed change from its diff, in code, before any human sees it. Two scales: how reversible the change is (R0 to R4) and how far it reaches (B0 to B3). The R and B scales are this library's own.

## Problem

"May the agent do this unattended?" is usually answered per request by a person. At volume, people approve almost everything: one vendor measured 93% of permission prompts approved ([SG-9](../references/sources.md)). Approval at that rate is not a control. It gives a feeling of safety and no filtering.

## Solution

A classifier reads the diff and its target and returns a reversibility class and a blast-radius class. The rules are data, not prose. When the classifier cannot decide, the answer is the highest class. It fails closed.

| Class | Meaning | Example |
|-------|---------|---------|
| R0 Inert | No runtime effect | A test, a log field, a doc |
| R1 Flag-reversible | New path behind a flag that defaults off; undo is one config write | A guarded code path |
| R2 Deploy-reversible | Revert and redeploy restores the prior state; no data written in a new shape | A pure logic fix |
| R3 Data-forward | Writes data the old version cannot read, or migrates a schema | A migration, a backfill |
| R4 External or irreversible | Money moved, message sent, third-party state changed, data deleted | A refund, an email, a chain transaction |

| Class | Reach | How it is measured |
|-------|-------|--------------------|
| B0 | One journey, internal | Which stack tests touch the changed files |
| B1 | One service, all users | Files owned by one service |
| B2 | A cross-service contract | A change to a public interface (the deep-module seam, [Pattern 0.1](../L0-foundation.md#pattern-01--deep-modules)) |
| B3 | Money, auth, PII or audit | Paths on an owner-maintained list |

Owner-listed paths and CI workflow files always need a person ([AN-29](../references/sources.md)).

## In Practice

In [`examples/repair-loop/`](../../examples/repair-loop/README.md) the rules are data in `shared/config/reversibility.json`: an ordered list of `{glob, reversibility, blast}` entries, an `unknown` class and `content` rules. Each changed file takes its first matching glob, content rules can raise the class, and the diff takes the highest class across its files. An excerpt:

```json
{
  "unknown": { "reversibility": "R4", "blast": "B3" },
  "paths": [
    { "glob": "tests/**", "reversibility": "R0", "blast": "B0" },
    { "glob": "app/src/routes/**", "reversibility": "R2", "blast": "B0" },
    { "glob": "app/migrations/**", "reversibility": "R3", "blast": "B1" },
    { "glob": ".github/**", "reversibility": "R4", "blast": "B3" }
  ],
  "content": [
    { "name": "external-effect", "pattern": "\\b(sendMail|smtplib)\\b|\\bfetch\\(", "reversibility": "R4" }
  ]
}
```

A file that matches no glob takes the `unknown` class, R4 and B3.

Score the classifier with the context-eval method ([Pattern 4.6](../L4-standards-measurement.md#pattern-46--context-eval)), with one change: exact scoring only. A half-correct class on an irreversible action is a miss.

Read the diff, not the description. A "pure logic" change that alters how amounts are rounded is R4 in a payments system. Keep the owner-listed paths current, because classification drifts as code moves.

The classes feed the gate in [Pattern 1.10](1.10-production-gate-progressive-confirmation.md). Which class may merge with no person, at which grant, is one table in [Pattern 1.11](1.11-repair-budget-circuit-breaker-stop.md#grants-and-repair-capability): R0 and R1 at B0 from A4, R2 at B0 for named classes at A5, and never R3 or R4.

## Anti-Pattern

- **Classifying from the commit message** or the agent's own summary.
- **Failing open.** An unknown change treated as low risk.
- **An unmaintained owner list.** The B3 class is only as good as the list.
- **A human approval for every change.** Decide about classes of change, not each instance.
