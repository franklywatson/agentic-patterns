# Pattern 1.11 — Repair Budget, Circuit Breaker and Stop Authority

Evidence for this pattern is Thin. Budgets and breakers have one position paper behind them. Stop and restore authority has vendor guidance. No source shows a breaker that lowers an agent's autonomy on outcome data in practice. One vendor names it as not yet built ([AN-29](../references/sources.md)).

## Problem

Automatic repair at production volume oscillates: repair, regress, revert, repair again. Zero-defect tolerance turns every alert into a trigger. A healthy agent can still take harmful actions ([PO-14](../references/sources.md)). Without limits and a stop, the loop runs until a human notices.

## Solution

Four controls, all enforced by code outside the agent.

**Attempt budget.** Each incident fingerprint gets a fixed number of automatic attempts, for example one. After that, a human takes over. A per-service daily budget and global caps on spend and turns bound the total.

**Cooldown.** After any rollback, the same fingerprint is not retried until a set time has passed.

**Circuit breaker on outcomes.** Two rates are measured: the revert rate of repairs, and the recurrence rate (the same fingerprint returning within N days of a repair marked confirmed). When either crosses its threshold, the workflow drops one grant automatically: from unattended to human-approved, then to read-only diagnosis. Raising it again is a named human decision recorded in the register. Use two thresholds. The trip level is worse than the reset level, so the grant does not flap.

**Stop authority.** A named person or role can stop the workflow with one switch. The switch is tested on a schedule. A named role approves restore after any incident the agent caused. The stop belongs to an on-call owner, not a committee.

### Grants and repair capability

The grants A1 to A5 are defined in [the README](../../README.md#how-far-a-team-can-let-go). A grant is what one named workflow may do. The table shows what repair capability is defensible at each.

| Grant | Defensible repair capability |
|-------|------------------------------|
| A3 | The agent drafts a reproduction and a fix pull request from an incident record. A human merges, with an evidence bundle. |
| A4 | First-pass diagnosis on every incident. R0 and R1 repairs at B0 pass through the gate with a canary, budgets, a tested stop and a register entry. |
| A5 | Grants move on revert and recurrence evidence. Workflows are retired. R2 repairs run unattended for named classes only. |
| Any grant | Unattended repair of R3 and R4 changes is not supported. |

Unattended repair of R3 and R4 changes is not supported at any grant, for three reasons. A data-forward or external action cannot be undone by a rollback, so the confirmation window protects nothing. No source shows unattended repair of incidents at all, only of maintenance. And no published case names who answers for an agent's harmful action. The reference domain, a trading bot, is mostly R4: on-chain transactions cannot be reversed.

## In Practice

The breaker is a small state machine over the repair history, with its thresholds in the repair policy config.

```python
def next_grant(grant: str, reverts: int, recurrences: int, policy: Policy) -> str:
    if reverts >= policy.trip_reverts or recurrences >= policy.trip_recurrences:
        return lower(grant)
    return grant  # raising a grant is a recorded human decision, never automatic
```

`examples/repair-loop/` exercises it: a simulated recurrence after a confirmed repair drops the grant, and the stop switch is pulled and checked.

Recurrence detection depends on a stable fingerprint. A stack trace changes with the fix, so fingerprint on the failing journey and the error class, not on line numbers. Each workflow has a register entry: owner, sponsor, permitted classes, budgets, stop switch, date of the last stop test, and a review date.

## Anti-Pattern

- **A breaker that only alerts.** It must change the grant.
- **A stop nobody may pull.** Name the person and test the switch.
- **Automatic restore.** The agent never raises its own grant.
- **Counting repairs as success.** See the repair metrics in [Pattern 4.4](../L4-standards-measurement.md#pattern-44--agentic-development-metrics).
